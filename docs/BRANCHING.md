# Гілкова стратегія

Спрощений Git Flow:

| Гілка | Призначення | Куди розгортається |
| --- | --- | --- |
| `main` | стабільний код, готовий до production | staging → production (з ручним затвердженням) |
| `develop` | інтеграція завершених функцій | staging |
| `feature/<назва>` | розробка окремої функції | — (лише CI) |

Правила:

1. Нова функція — гілка `feature/*` від `develop`, злиття в `develop` через
   pull request після зеленого CI.
2. Поки над проєктом працює один розробник, дрібні виправлення (конвеєр,
   документація, невеликі зміни сервісів) дозволено комітити напряму в
   `develop` — CI однаково перевіряє кожен push. Так були зроблені перші
   виправлення етапу 1.
3. Реліз — pull request `develop` → `main`; після злиття Production Pipeline
   розгортає образ у staging і чекає затвердження для production.
4. Прямі коміти в `main` не використовуються (крім початкового налаштування).
